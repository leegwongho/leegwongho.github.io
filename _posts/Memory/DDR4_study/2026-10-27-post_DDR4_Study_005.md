# Introduction

AXI로 256비트씩 주소를 올리면 주소는 **32씩 증가**합니다. 그러면 `AWADDR`의 하위 5비트는 항상 0이고, 주소 매핑이 낮은 비트에 **bank**를 두면 **bank는 항상 0이라 의미가 없는 것 아닌가?** 하는 의문이 들었습니다.

결론부터 말하면 **bank는 죽지 않습니다.** 오히려 **순차 접근에서 가장 자주 바뀌는 비트가 bank**이고, 그것이 006에서 특정 매핑이 가장 빨랐던 이유입니다.

> 이 글은 PG150의 **주소 매핑 설명**을 기준으로 합니다. 정확한 비트 위치는 **생성한 IP의 설정**에 따라 다르므로 직접 확인해야 합니다.

---

# 의문이 풀린 순서

처음에는 이런 생각이었습니다.

1. "하위 5비트가 0으로 패딩되고 5비트부터 bank[0]이 시작한다"는 설명이 **PG150에 있나?** → 그런 문장은 문서에 **없었습니다.**
2. 하위 5비트 [4:0] + bank 2비트 [6:5] + column 10비트 [16:7] 이면 row 16비트가 어떻게 들어가나? → **5 + 2 + 10 + 16 = 33비트**로 주소 폭에 맞지 않는 모순을 직접 계산했습니다.
3. 근거 없는 설명에 의존하지 않고 **PG150을 직접** 확인했습니다.

찾은 것은 세 가지입니다.

- **AXI Byte Address Mapping** 표
- **`C_S_AXI_ADDR_WIDTH` 계산식**
- "The AXI shim converts the address ... The UI Data Width is always eight times the PAYLOAD_WIDTH" 문단

---

# 1. AXI 주소는 바이트, app_addr는 메모리 폭 단위

PG150의 매핑 표에서 UI가 256비트이고 메모리가 32비트일 때는 다음과 같습니다.

```
AxADDR = { app_addr, 2'b00 }
```

즉 **`app_addr = AxADDR >> 2`** 입니다.

- AXI 주소는 **바이트 주소**입니다.
- `app_addr`는 **메모리 데이터 폭(32비트 = 4바이트) 단위** 주소입니다.
- `app_addr` 한 칸은 **4바이트**(x32 한 번)입니다.

# 2. AWADDR를 32씩 올리면 app_addr는 8씩 오른다

256비트 = BL8 한 번이므로 **한 번에 8칸**(= 32바이트)을 씁니다.

- `AWADDR`를 32 올리면 `app_addr`는 **8 오릅니다.**
- 003에서 본 Native 컨트롤러가 `wr_addr + 8`을 쓴 것과 같은 이유입니다.

# 3. 항상 0인 것은 bank가 아니라 column 하위 3비트

`app_addr[2:0]`은 **버스트 안의 순서를 가리키는 column 비트**이고, BL8 정렬 접근에서는 **항상 0**입니다. 비트가 사라지는 것은 아니고 주소 폭에 그대로 있습니다. ("column 3비트가 오프셋에 흡수된다"는 설명은 이 부분만 반쯤 맞힌 것입니다.)

# 4. bank group과 bank는 바로 그 위

PG150의 **ROW_COLUMN_BANK** 배치는 `app_addr` 기준으로 다음과 같이 읽힙니다.

> **확인 필요**: PG150의 주소 순서 옵션(IP 파라미터)에는 `ROW_COLUMN_BANK` 외에 bank group을 더 잘게 섞는 `..._INTLV` 같은 변형도 있습니다. 006에서 "Row → Column → Bank (interleave)"로 부른 매핑이 정확히 어느 옵션 값이었는지는 생성한 IP의 파라미터로 확인해 두어야 합니다. 이 시리즈에서 매핑 이름은 **상위 비트 → 하위 비트 순서**로 씁니다.

```
app_addr 하위 → 상위

[ column 하위 3비트 ][ BG, BA ][ 나머지 column ][ row ]
 (BL8 안의 순서)       (bank 선택)                 (맨 위)
```

- `app_addr`가 **8씩 오르면**, 하위 3비트는 변하지 않고 **바로 위의 bank group / bank 비트가 가장 먼저 바뀝니다.**
- 즉 **연속 주소가 매번 다른 bank로** 갑니다.
- 한 bank가 ACT/PRE(활성/프리차지)를 하는 동안 **다른 bank가 일합니다.** 이것이 **bank interleaving**입니다.

## DDR4만의 이유: Bank Group과 tCCD

DDR4에서는 bank를 **Bank Group(BG)** 으로 묶고, 연속된 읽기(또는 쓰기) 사이의 최소 간격이 **같은 BG냐 다른 BG냐**에 따라 다릅니다.

| 연속된 두 접근 | 최소 간격 | 의미 |
|----------------|-----------|------|
| **다른** Bank Group | **tCCD_S** = 4 nCK | BL8 데이터(4 nCK)를 쉬지 않고 이어 보낼 수 있다 |
| **같은** Bank Group | **tCCD_L** (4 nCK보다 길다) | 데이터 사이에 빈 클럭이 생긴다 |

그래서 DDR4에서 순차 대역폭을 끝까지 쓰려면 **연속 접근이 Bank Group을 번갈아** 가야 합니다. BG 비트가 `app_addr`의 낮은 쪽에 오는 매핑이 순차 접근에서 유리한 직접적인 이유이고, DDR3에는 없던 차이입니다. tCCD_L의 정확한 값은 속도 등급에 따라 다르므로 **칩 데이터시트에서 확인 필요**합니다.

x16 칩은 Bank Group이 **2개**(BG 1비트)뿐이라, 번갈아 쓸 수 있는 BG가 둘밖에 없다는 점도 함께 기억해 둡니다.

처음 의문이었던 "하위 5비트가 0이면 bank가 죽는다"는 **매핑표를 `AWADDR`에 직접 대었기 때문에** 생긴 오해였습니다. 매핑표는 `AWADDR`에서 2비트를 뗀 **`app_addr`에 적용**되고, 그래서 항상 0인 것은 column 하위 3비트뿐입니다.

> 정확한 비트 위치는 구성에 따라 다르므로 **생성된 IP의 파라미터로 확인**합니다.

# 28 / 29 / 31비트가 어긋난 이유

> "실제로 AXI로 바꾸면 addr가 31비트가 되는데, 이건 app 28비트에 5비트를 더한 게 아닌 상황이라 이상하다."

같은 문서로 풀립니다.

| 항목 | 계산 | 값 |
|------|------|-----|
| `app_addr` 폭 (x16 **8Gb** 칩) | row 16 + col 10 + bank 2 + BG 1 | **29비트** |
| `app_addr` 폭 (x16 **4Gb** 칩, 예제나 이전 IP) | row 15 + col 10 + bank 2 + BG 1 | **28비트** |
| AXI 주소 폭 (PG150 식) | 0 + 16 + 10 + 2 + 1 + log2(32) - 3 | **31비트** = 29 + 2 |
| 주소 공간 | 2^29 × 4바이트 | **2GB** (1GB 칩 2개, x32 구성) |

- AXI 31비트는 **"app 28 + 5"가 아니라 "app 29 + 2"** 입니다.
- 28비트는 **4Gb 칩** 기준값이었고, 실제 보드의 칩은 row가 한 비트 더 많은 **8Gb**였습니다.
- 그래서 **IP의 Memory Part 설정을 실제 칩으로 바꾸는 것은 단순한 이름 변경이 아닙니다.** row 폭(주소 공간의 절반), 속도 등급, 타이밍 파라미터가 함께 바뀝니다.

(004에서 "IP 설정이 실제 메모리와 같아야 한다"고 한 이유입니다.)

# 기초 사실 두 가지

- **용량**: x16 8Gb 칩 = 512M × 16비트 = **8Gb = 1GB**.
- **무엇이 비싼가**: 같은 bank에서 row가 바뀌면 **PRE(tRP) → ACT(tRCD) → READ(CL)** 를 모두 거칩니다. 다른 bank는 미리 열어 둘 수 있어 **지연을 숨길 수 있습니다.**

비용 순서는 대체로 이렇습니다.

> **column ≪ bank < row**

- **column 변경**: 같은 row 안의 접근이라 가장 쌉니다. (page hit)
- **bank 변경**: 미리 열어 두면 숨길 수 있습니다. 같은 BG 안인지, 다른 BG인지도 차이를 만듭니다(tCCD_L / tCCD_S).
- **row 변경**: 같은 bank에서 PRE + ACT + CAS를 모두 치릅니다. 가장 비쌉니다. (page miss)

## 같은 bank의 row miss는 tRC마다 한 번

같은 bank에서 row를 바꾸려면, 앞 row를 연 시점부터 다음 row를 열 때까지 최소 **tRC(= tRAS + tRP)** 가 지나야 합니다. DDR4-2000~2400급에서 대략 **45~48 ns**입니다(정확한 값은 **칩 데이터시트에서 확인 필요**).

즉 **같은 bank에서만 row miss가 이어지면, 아무리 요청을 빨리 넣어도 tRC마다 한 번**밖에 처리할 수 없습니다. 006의 랜덤 결과가 바로 이 숫자로 설명됩니다.

반대로 bank를 잘 흩으면 이 한계는 사라지고, 다음 한계는 **tRRD(ACT 사이 최소 간격)와 tFAW(일정 시간 안에 ACT 최대 4번)** 가 됩니다. 이 값들은 tRC보다 훨씬 짧아서, bank를 잘 흩은 랜덤 접근은 지금보다 몇 배 높은 처리율이 가능합니다.

006의 모든 결과가 이 순서로 설명됩니다.

# What I Learned

- AXI 주소는 **바이트**, `app_addr`는 **메모리 폭 단위**이고 `app_addr = AxADDR >> 2` (x32, UI 256비트 기준)이다.
- `AWADDR` 32 증가는 `app_addr` **8 증가**다.
- 항상 0인 것은 bank가 아니라 **column 하위 3비트(BL8 안의 순서)** 이다.
- **ROW_COLUMN_BANK** 배치에서는 순차 접근에서 가장 먼저 바뀌는 것이 **bank group / bank**이고, 이것이 interleaving이다.
- 주소 폭은 칩 용량에서 결정되고 **28 / 29 / 31비트** 차이는 4Gb/8Gb 칩과 AXI 변환(+2)으로 설명된다.
- 비용은 **column ≪ bank < row**이며, row 변경이 가장 비싸다. 같은 bank의 row miss는 **tRC마다 한 번**이 한계다.
- DDR4는 **Bank Group**이 있어서, 연속 접근이 BG를 번갈아 가야(tCCD_S) 데이터 버스를 쉬지 않고 쓸 수 있다.
- 출처 없는 설명이 나오면 **PG150을 직접 확인**한다.
