# Introduction

100Gb Ethernet(100GbE)은 IEEE 802.3 표준에서 정의한 초고속 Ethernet 규격으로, 최대 **100 Gbps**의 데이터 전송 속도를 제공합니다.

오늘날 데이터센터, 클라우드, AI 서버, HPC(High Performance Computing) 환경에서는 대용량 데이터를 빠르게 처리하기 위해 100Gb Ethernet이 널리 사용되고 있습니다.

이번 프로젝트에서도 AMD(Xilinx)의 **100G Ethernet CMAC IP**를 이용하여 FPGA에서 100Gb Ethernet Link를 구성하고 Packet을 송수신하는 것을 목표로 하였습니다.

이번 글에서는 프로젝트를 시작하기에 앞서 100Gb Ethernet이 무엇인지, 그리고 FPGA에서는 어떤 구조로 구현되는지를 살펴보겠습니다.

---

# Evolution of Ethernet

Ethernet은 지속적으로 전송 속도가 향상되어 왔습니다. (표준 제정 순서대로 정리)

| Standard | Speed | IEEE Standard |
|----------|-------|---------------|
| Ethernet | 10 Mbps | IEEE 802.3 |
| Fast Ethernet | 100 Mbps | IEEE 802.3u |
| Gigabit Ethernet | 1 Gbps | IEEE 802.3z (광) / 802.3ab (구리) |
| 10 Gigabit Ethernet | 10 Gbps | IEEE 802.3ae |
| 40 Gigabit Ethernet | 40 Gbps | IEEE 802.3ba |
| **100 Gigabit Ethernet** | **100 Gbps** | **IEEE 802.3ba / 802.3bj / 802.3bm / 802.3cd** |
| 25 Gigabit Ethernet | 25 Gbps | IEEE 802.3by |

100GbE는 하나의 표준이 아니라 여러 개정으로 확장되었습니다.

| 개정 | 주요 내용 |
|------|-----------|
| 802.3ba (2010) | 40G/100G 최초 정의, 10 × 10G 기반 |
| 802.3bj (2014) | 4 × 25G 백플레인/구리, **RS-FEC(Clause 91)** 도입 |
| 802.3bm (2015) | 4 × 25G 광 (100GBASE-SR4 등) |
| 802.3cd (2018) | 50G/레인 기반 100G (2 × 50G PAM4) |

이 프로젝트에서 쓴 4 × 25G 구성과 RS-FEC 설정(004)은 802.3bj/bm에서 정의된 내용과 연결됩니다.

100Gb Ethernet은 현재 데이터센터 및 고성능 네트워크에서 가장 널리 사용되는 인터페이스 중 하나이며, 최근에는 200GbE와 400GbE 환경도 빠르게 확산되고 있습니다.

---

# Why 100G Ethernet?

네트워크 대역폭 요구사항은 지속적으로 증가하고 있습니다.

대표적인 예는 다음과 같습니다.

- AI Training Cluster
- Cloud Computing
- High Performance Computing (HPC)
- Storage Network
- Data Center Spine Network

이러한 환경에서는 기존 10GbE 또는 25GbE만으로는 충분한 대역폭을 확보하기 어렵기 때문에 100GbE 이상의 인터페이스가 요구됩니다.

---

# How Does 100G Ethernet Work?

100Gb Ethernet은 단순히 하나의 선으로 100Gbps를 전송하는 것이 아닙니다.

본 프로젝트에서 사용한 QSFP28 기반 100Gb Ethernet(**CAUI-4**)은 **4개의 Lane**을 이용하여 하나의 100Gb Link를 구성합니다.

```text
             100G Ethernet (CAUI-4)

      Lane0   25.78125 Gbps
      Lane1   25.78125 Gbps
      Lane2   25.78125 Gbps
      Lane3   25.78125 Gbps

      선로 속도 합계  103.125 Gbps
      64B/66B 제거 후 100 Gbps
```

## 숫자가 어떻게 맞아떨어지나

- 64B/66B 인코딩은 64비트 데이터마다 2비트 헤더를 붙이므로, 선로 속도의 64/66만 실제 데이터입니다.
- 103.125 × 64 / 66 = **100 Gbps**
- CMAC 내부 데이터 경로는 512비트(64 Byte) 폭이고, 100 Gbps를 처리하려면 약 195 MHz 이상이 필요합니다. 실제로는 여유를 두고 **322.266 MHz**로 동작하며, 이것이 004와 007에서 계속 나오는 `txusrclk2` 주파수입니다.

## 물리 레인과 PCS 레인

4개의 물리 Lane 위에서 PCS는 데이터를 **20개의 PCS lane**으로 나누어 보냅니다(각 물리 Lane에 PCS lane 5개). 수신 측은 각 PCS lane의 정렬 마커를 찾아 **20개를 다시 정렬(deskew)** 하고 원래 순서로 합칩니다. 004에서 링크 판단 기준으로 쓴 `stat_rx_aligned`는 바로 이 정렬이 모두 끝났다는 뜻입니다.

# FPGA Architecture

UltraScale+의 CMAC은 **하드 블록**이며, MAC뿐 아니라 **PCS와 선택적 RS-FEC까지** 포함합니다. GT Transceiver는 PMA(직렬화/역직렬화)를 담당합니다.

```text
               User Logic
                    │
           AXI4-Stream (512 bit, 322.266 MHz)
                    │
     +-------------------------------+
     |           CMAC 블록            |
     |  MAC  →  (RS-FEC)  →  PCS      |
     +-------------------------------+
                    │
     +-------------------------------+
     |  GT Transceiver ×4 (PMA)       |
     +-------------------------------+
                    │
                 QSFP28
                    │
           Optical Fiber / DAC
                    │
          Traffic Generator
```

각 블록의 역할은 다음과 같습니다.

| Block | 위치 | Role |
|-------|------|------|
| User Logic | FPGA 패브릭 | Packet 생성 및 처리 |
| AXI4-Stream | | Packet Interface |
| MAC | CMAC 블록 | Ethernet Frame 처리 (FCS, 길이 검사, Pause 등) |
| RS-FEC | CMAC 블록 (선택) | 오류 정정 |
| PCS | CMAC 블록 | 64B/66B 인코딩, 스크램블링, PCS lane 분배와 정렬 |
| PMA | GT Transceiver | Parallel ↔ Serial 변환, CDR |
| QSFP28 | 보드 | 광/전기 인터페이스 |

이번 프로젝트에서는 이러한 전체 구조를 직접 구성하고 Link Bring-up을 수행하였습니다.

---

# Why Can't We Use Normal FPGA I/O?

100Gb Ethernet은 Lane당 25Gbps가 넘는 매우 높은 직렬 전송 속도를 요구합니다.

일반 FPGA GPIO는 이러한 속도를 지원하지 못하기 때문에 **GT Transceiver**와 같은 전용 High-Speed Serial Interface를 사용해야 합니다.

GT Transceiver는 다음과 같은 기능을 제공합니다.

- Serializer / Deserializer (SerDes)
- Clock Data Recovery (CDR)
- Equalization
- High-Speed Clocking

100Gb Ethernet뿐만 아니라 PCI Express, JESD204, DisplayPort 등 다양한 고속 인터페이스에서도 GT Transceiver가 사용됩니다.

---

# Where Does CMAC Fit?

많은 사람들이 처음 FPGA Ethernet을 접하면 CMAC이 MAC 기능만 한다고 생각하거나, 반대로 Ethernet 전체를 담당한다고 생각하기 쉽습니다.

실제로 UltraScale+ CMAC은 **MAC + PCS(+ RS-FEC)** 를 담당하고, 나머지는 바깥에 있습니다.

```text
Application
     │
 AXI4-Stream
     │
 ┌───────────┐
 │ CMAC      │  ← MAC + PCS (+ RS-FEC)
 └───────────┘
     │
 GTY (PMA)
     │
 QSFP28
     │
 Fiber / DAC
```

즉,

- CMAC은 Ethernet Frame 처리(MAC)와 인코딩·레인 정렬(PCS)을 담당하고
- GT Transceiver는 실제 직렬 데이터 송수신(PMA)을 담당하며
- QSFP28 모듈과 그 제어는 보드와 사용자 로직의 몫입니다.

그래서 CMAC IP를 생성할 때 속도뿐 아니라 Lane 구성, 클럭, FEC 같은 **PCS/PMA 쪽 설정**까지 함께 정해야 합니다(004). 이 역할 구분을 이해하는 것이 이후 CMAC Bring-up 과정에서 매우 중요합니다.

# Key Takeaways

- 100Gb Ethernet은 IEEE 802.3 표준으로 정의된 고속 Ethernet 인터페이스이며, 여러 개정(ba/bj/bm/cd)으로 확장되었다.
- CAUI-4는 25.78125 Gbps × 4 Lane이고, 64B/66B를 빼면 100 Gbps가 된다.
- UltraScale+ CMAC은 **MAC + PCS(+ RS-FEC)** 를 포함하는 하드 블록이고, PMA는 GT Transceiver가 담당한다.
- PCS는 4개 물리 Lane 위에 20개 PCS lane을 쓰며, `stat_rx_aligned`는 이 정렬이 끝났다는 뜻이다.
- CMAC은 Ethernet 시스템의 일부이며, 전체 구조를 이해하는 것이 Bring-up의 첫걸음이다.
