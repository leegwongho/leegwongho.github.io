# Packet vs Frame

네트워크에서는 계층마다 데이터 단위를 부르는 이름이 다릅니다.

| Layer | Unit |
|-------|------|
| L2 (Data Link, Ethernet) | **Frame** |
| L3 (IP) | Packet |
| L4 (TCP/UDP) | Segment / Datagram |

CMAC은 Ethernet MAC이므로 **L2, 즉 Frame 단위**로 동작합니다. 그래서 TPG도 임의의 데이터가 아니라 Ethernet Frame 형태로 만들기로 했습니다.

---

# Ethernet Frame Structure

기본 Ethernet II 프레임은 아래와 같이 구성됩니다.

```
| Preamble | SFD | Dest MAC | Src MAC | EtherType | Payload   | FCS  |
|   7 B    | 1 B |   6 B    |   6 B   |   2 B     | 46~1500 B | 4 B  |
```

| Field | Size | Description |
|-------|------|-------------|
| Preamble | 7 B | 수신 측이 비트 타이밍을 맞추기 위한 `10101010...` 패턴 |
| SFD | 1 B | 프레임 시작을 알리는 Start Frame Delimiter (`0xAB`) |
| Destination MAC | 6 B | 받는 쪽 주소 |
| Source MAC | 6 B | 보내는 쪽 주소 |
| EtherType | 2 B | Payload의 종류. 예: IPv4 `0x0800`, ARP `0x0806`, IPv6 `0x86DD` |
| Payload | 46 ~ 1500 B | 실제 데이터 (IP 패킷 등) |
| FCS | 4 B | 프레임 오류를 검출하는 CRC-32 |

## Size

- Destination MAC부터 FCS까지의 길이가 **최소 64 B, 최대 1518 B**입니다. (VLAN 태그가 붙으면 4 B가 늘어납니다.)
- Payload가 46 B보다 짧으면 Padding으로 채워 최소 길이를 맞춥니다.
- 프레임 사이에는 최소 **12 B의 IFG(Inter-Frame Gap)** 가 필요합니다.
- Preamble과 SFD는 프레임 길이에 포함하지 않는 것이 일반적입니다.

**64 B** 라는 최소 길이는 이 프로젝트에서 중요한 기준이 됩니다. 다음 글에서 이 숫자와 다시 만납니다.

---

# IPv4 Frame의 쌓임

가장 흔한 IPv4/UDP 프레임은 다음과 같이 헤더가 쌓입니다.

```
[ Ethernet Header 14 B ][ IPv4 Header 20 B ][ UDP Header 8 B ][ Data ][ FCS 4 B ]
```

EtherType이 `0x0800`이면 그 뒤를 IPv4로 해석합니다. 이 구조는 이후 RSS나 패킷 분배를 다룰 때 **필드를 어느 위치에서 읽는지**의 기준이 되므로 알아 두어야 합니다.

---

# AXI4-Stream으로 Frame 보내기

CMAC의 사용자 인터페이스는 AXI4-Stream입니다. 이번 IP 설정에서 데이터 폭은 **512비트(64 Byte)** 였기 때문에, 64 B 프레임은 **한 번의 beat** 로 전송할 수 있습니다.

AXI4-Stream에서 아래 신호가 프레임을 표현합니다.

| Signal | Width | Meaning |
|--------|-------|---------|
| `tdata` | 512 bit | 프레임 데이터 |
| `tvalid` | 1 bit | 데이터가 유효함 |
| `tready` | 1 bit | 받는 쪽이 받을 준비가 됨 |
| `tlast` | 1 bit | 프레임의 마지막 beat |
| `tkeep` | **64 bit** | 각 Byte가 유효한지 표시 (Byte당 1비트) |
| `tuser` | 1 bit | 에러 표시 |

여기서 **`tkeep`** 은 Byte마다 1비트이므로 512비트 버스에서는 **64비트**입니다. 64 B 프레임이라면 64비트가 모두 1이어야 합니다. 이 폭은 다음 글의 핵심이 됩니다.

# 직접 만든 TPG

처음부터 Ethernet Frame 형태에 맞춰 TPG를 직접 작성했습니다.

## Frame 구성

| Field | Value |
|-------|-------|
| Destination MAC | `55:44:33:22:11:00` |
| Source MAC | `00:11:22:33:44:55` |
| EtherType | `0x0800` (IPv4) |
| Payload | 46 B |
| FCS 위치 | `DEADBEEF` 로 채움 |
| 총 길이 | 14 + 46 + 4 = **64 B** |

512비트 1 beat로 한 번에 전송하며, `tkeep`은 `64'hFFFF_FFFF_FFFF_FFFF`, `tuser`는 0으로 두었습니다.

## 상태 머신

```
IDLE → WAIT_READY → SEND → DONE
```

- `tpg_start` 입력이 들어오면 패킷 **한 개**를 전송합니다.
- `tready`를 확인한 뒤 `tvalid`와 데이터를 내보냅니다.

## IP 쪽 설정

TPG와 함께 CMAC의 다음 옵션을 설정했습니다.

- FCS 삽입/제거: 켬
- Preamble/SFD 검사: 끔
- 최소 패킷 길이: 64

즉 CMAC이 받아들이는 최소 길이도 **64 B**로 정해 두었습니다.

# What I Learned

- "패킷을 만든다"는 말은 먼저 **어떤 계층의 단위인지**를 정해야 한다.
- Ethernet Frame은 Destination MAC, Source MAC, EtherType, Payload, FCS로 구성되며 최소 64 B, 최대 1518 B이다.
- AXI4-Stream 폭이 512비트이면 `tkeep`은 64비트이다.
- 이후 RSS, 패킷 분배처럼 헤더 필드를 읽는 작업의 출발점도 이 프레임 구조다.
