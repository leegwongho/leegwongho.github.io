# Introduction

001~003에서 CRC와 PRBS의 병렬 식을 풀어 봤습니다. 이 식들은 틀리기 쉽고, 틀려도 **그럴듯한 값**이 나옵니다. 마지막 글에서는 식을 **어떻게 검증하는지**, 그리고 실무에서 자주 만나는 **함정**을 정리합니다.

---

# 1. 검증의 기본: 직렬 모델이 기준이다

병렬 식은 **직렬 1스텝 규칙을 N번 적용한 결과**입니다. 그래서 검증 기준은 항상 같습니다.

> **같은 입력을 직렬 모델에 N스텝 돌린 결과와 병렬 식의 결과가 같은가?**

| 대상 | 검증 방법 |
|------|-----------|
| CRC 병렬 식 | 직렬 CRC 모델로 16스텝 돌린 결과와 비교, **확인값** 확인 |
| PRBS 병렬 식 | 직렬 점화식 시뮬레이션과 **전체 출력 비교**, **주기** 확인 |
| 새 다항식 | 직렬 모델부터 만들고 병렬 식을 그것에서 유도 |

## CRC: 확인값(check value)

CRC에는 **표준 확인값**이 있습니다. 문자열 `"123456789"`를 넣었을 때 나와야 하는 값입니다.

| 규격 | 확인값 |
|------|--------|
| CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF, MSB-first) | **0x29B1** |

```python
def crc16_serial(bits, c=0xFFFF):
    for b in bits:
        fb = ((c >> 15) & 1) ^ b
        c = (c << 1) & 0xFFFF
        if fb:
            c ^= 0x1021
    return c

def msb_first_bits(data: bytes):
    return [(byte >> i) & 1 for byte in data for i in range(7, -1, -1)]

assert crc16_serial(msb_first_bits(b"123456789")) == 0x29B1
```

시뮬레이션에서도 **같은 확인값**이 나오는지를 보면 비트 순서, 초기값, 바이트 순서가 한 번에 검증됩니다.

## PRBS: 주기 측정

PRBS는 **주기**로 검증합니다. 상태를 초기값에서 시작해 초기 상태로 돌아올 때까지 센 값이 **2^n - 1**인지 봅니다.

```python
def period(taps, L):
    """u(n+L) = XOR of u(n+t) for t in taps"""
    s = [1] * L
    start = tuple(s)
    n = 0
    while True:
        new = 0
        for t in taps:
            new ^= s[t]
        s = s[1:] + [new]
        n += 1
        if tuple(s) == start:
            return n

print(period([0, 3, 4, 7], 12))     # 4095  (= 2^12 - 1)
print(period([0, 1, 3, 4], 13))     # 8191  (= 2^13 - 1)
print(period([0, 9], 13))           # 7161  (x^13 + x^4 + 1, 최대 길이 아님)
```

마지막 줄이 보여 주듯, **흔히 쓸 것 같은 다항식(x^13 + x^4 + 1)이 최대 길이가 아닐 수 있습니다.** 직접 돌려 보지 않으면 모릅니다.

이유도 설명됩니다. x^13 + x^4 + 1은 **x^3 + x^2 + 1로 나누어떨어집니다.** 최대 길이가 되려면 다항식이 먼저 **기약(irreducible, 더 작은 다항식으로 인수분해되지 않음)** 이어야 하는데, 인수분해되는 다항식은 처음부터 그 조건을 만족하지 못합니다. 그래서 주기를 재기 전에 **작은 다항식들로 나눠 보는 것**도 빠른 판별법이 됩니다.

```python
def pmod(a, b):                           # GF(2) 다항식 나머지
    db = b.bit_length() - 1
    while a and a.bit_length() - 1 >= db:
        a ^= b << (a.bit_length() - 1 - db)
    return a

f = (1 << 13) | (1 << 4) | 1               # x^13 + x^4 + 1
print([bin(d) for d in range(2, 1 << 7) if pmod(f, d) == 0])   # ['0b1101'] = x^3 + x^2 + 1
```

> 기약이라고 모두 최대 길이(원시)인 것은 아닙니다. 기약 판별은 "확실히 아닌 것"을 빨리 거르는 용도이고, 최종 확인은 주기 측정입니다.

## 병렬 식과 직렬 모델 비교

병렬 식에서 나온 XOR 목록(`{0, 3, 4, 5, 7, 8, 9}` 같은 집합)을 **상태에서 직접 계산**한 값과 직렬로 12스텝 돌린 값을 비교합니다.

```python
def prbs12_serial(bits12):                 # bits12[k] = u(k), 12개
    u = list(bits12)
    for n in range(12):
        u.append(u[n] ^ u[n + 3] ^ u[n + 4] ^ u[n + 7])
    return u[12:]                          # u(12) ~ u(23)

ROWS = [                                   # 003의 표 (row 0 ~ 11)
    [0, 3, 4, 7], [1, 4, 5, 8], [2, 5, 6, 9], [3, 6, 7, 10], [4, 7, 8, 11],
    [0, 3, 4, 5, 7, 8, 9], [1, 4, 5, 6, 8, 9, 10], [2, 5, 6, 7, 9, 10, 11],
    [0, 4, 6, 8, 10, 11], [0, 1, 3, 4, 5, 9, 11],
    [0, 1, 2, 3, 5, 6, 7, 10], [1, 2, 3, 4, 6, 7, 8, 11],
]

def prbs12_parallel(bits12):
    out = []
    for row in ROWS:
        v = 0
        for j in row:
            v ^= bits12[j]
        out.append(v)
    return out

import random
for _ in range(10000):
    x = [random.getrandbits(1) for _ in range(12)]
    assert prbs12_serial(x) == prbs12_parallel(x)
```

임의 입력으로 **여러 번** 돌려서 모두 같아야 식이 맞다고 볼 수 있습니다. 입력 12비트이므로 4096가지를 **전수**로 확인할 수도 있습니다.

## 선형이라서 단위 입력만 확인해도 된다

사실 더 짧은 방법이 있습니다. 병렬식은 GF(2) 위의 **선형 함수**입니다. 선형 함수는 **입력 비트를 하나씩만 1로 둔 경우(단위 벡터)** 의 결과가 맞으면, 모든 입력에서 맞습니다. 임의 입력은 단위 벡터들의 XOR이기 때문입니다.

| 대상 | 단위 입력 수 | 임의 입력 대신 |
|------|--------------|----------------|
| PRBS12 병렬식 | 12개 | 12번이면 완전 검증 |
| CRC16 병렬식 (데이터 폭 16) | 16개 | 16번이면 완전 검증 |

002의 **열 규칙 표가 바로 단위 입력 하나하나의 결과**입니다. 비트 j 하나만 1일 때 다음 상태의 어디가 1이 되는지를 적은 것이 그 표의 한 행이기 때문입니다.

```python
for j in range(12):
    x = [1 if k == j else 0 for k in range(12)]
    assert prbs12_serial(x) == prbs12_parallel(x)     # 12번으로 끝
```

> 이 방법은 **식이 정말 선형일 때만** 성립합니다. 초기값이나 최종 XOR처럼 상수가 더해지는 부분은 따로 확인합니다.

# 2. 식을 직접 만드는 절차

생성기에만 의존하지 않고, 어떤 다항식이든 직접 만드는 절차입니다.

1. **1스텝 규칙**을 적는다. 시프트 방향, fb를 만드는 비트, 데이터가 섞이는 자리, 어느 비트가 먼저 들어가는지를 정한다.
2. 각 비트를 값이 아니라 **"어느 원래 비트들의 XOR인가"라는 집합**으로 두고 1스텝 규칙을 N번 돌린다. **XOR은 집합의 대칭차**(같은 것 두 번 = 삭제)다.
3. 끝난 뒤의 집합이 곧 `next(i) <= ... xor ...` 식이다.
4. **검증**한다. 같은 입력을 직렬 모델 N스텝과 병렬 식에 넣어 비교하고, PRBS라면 **주기**가 2^n - 1인지, CRC라면 **확인값**이 나오는지 본다.

```python
def unroll(step, state_len, n_steps):
    """step: 집합(frozenset) 리스트를 받아 다음 집합 리스트를 돌려주는 함수"""
    s = [frozenset([i]) for i in range(state_len)]
    for _ in range(n_steps):
        s = step(s)
    return [sorted(x) for x in s]

# 예: 003의 PRBS13 갈루아 1스텝 (왼쪽 시프트, fb = s12, x^0/x^1/x^3/x^4에 섞임)
def galois13(s):
    fb = s[12]
    n = [None] * 13
    n[0] = fb
    for i in range(1, 13):
        n[i] = s[i - 1]
    for i in (1, 3, 4):
        n[i] = n[i] ^ fb                  # 집합의 대칭차 = XOR
    return n

for i, terms in enumerate(unroll(galois13, 13, 13)):
    print(i, terms)                        # next(0) = [0, 9, 10, 12] ...
```

이 방법으로 003의 모든 표를 다시 만들 수 있고, 새 다항식도 같은 방식으로 만들 수 있습니다.

# 3. 흔한 함정

## 비트 순서와 바이트 순서

| 함정 | 확인 방법 |
|------|-----------|
| **MSB-first인지 LSB-first인지** | 병렬 식은 `data_in(15)`이 먼저인지 `data_in(0)`이 먼저인지에 따라 달라진다. 002처럼 직접 전개해서 확인 |
| **16비트 워드 안의 바이트 순서** | 어느 바이트가 `data_in(15 downto 8)`에 들어가는지. **확인값 문자열**로 시뮬레이션 |
| **입출력 반전(reflect)** | 이더넷처럼 바이트를 LSB부터 보내는 규격은 입출력 비트를 뒤집어야 할 수 있다 |
| **최종 XOR** | 일부 규격은 결과에 0xFFFF를 XOR한다. 이 모델에는 없다 |

## 다항식 표기

같은 다항식도 **표기법**이 여러 가지입니다.

| 표기 | 예 (x^13 + x^4 + x^3 + x + 1) |
|------|--------------------------------|
| 최고차항과 상수항 포함 | 0x201B |
| 최고차항 생략 | 0x001B |
| 상수항(+1)을 생략하고 한 칸 민 형태 (Koopman 계열) | 0x100D |

0x201B를 오른쪽으로 한 칸 밀면 0x100D가 됩니다. 16진수만 보고는 어떤 다항식인지 알 수 없습니다. **표기 규칙(최고차항을 적는지, +1을 적는지)** 부터 확인해야 합니다.

## 다항식이 최대 길이인지

위에서 본 x^13 + x^4 + 1처럼 **외워 둔 다항식이 최대 길이가 아닐 수 있습니다.** 직접 주기를 측정합니다.

## 상태와 출력의 분리

003에서 본 것처럼, 시퀀스 중간에 다른 값을 끼워 넣는 구조라면 **PRBS 상태 레지스터를 출력과 분리**해야 합니다. 안 그러면 끼워 넣은 값이 상태를 덮어 시퀀스가 끊깁니다.

## 체커의 오류 수는 실제 오류 수가 아니다

003의 자기 동기화 PRBS 체커는 **비트 오류 하나를 여러 번 셉니다.** 체커가 보고한 오류 수를 그대로 BER로 쓰면 실제보다 크게 나옵니다. 체커가 어떤 방식인지(자기 동기화인지, 동기 후 내부 생성기와 비교하는지)부터 확인해야 합니다.

## 폭과 패딩

- PRBS13을 16비트로 내보낼 때 `"000" & prbs13`으로 채우면 PRBS13이 아닙니다. **한 클럭에 16스텝**을 풀어야 합니다.
- 출력 폭이 상태 길이와 다르면 **어느 비트가 먼저 나가는지**를 상대 장비 정의에 맞춰야 합니다.

# 4. AI가 만든 식을 어떻게 다룰까

LFSR을 공부하면서 가장 크게 느낀 점입니다. **AI의 설명이나 코드는 그럴듯하지만, 병렬 식처럼 틀리기 쉬운 부분은 틀릴 수 있습니다.** 이 학습 과정에서 확인한 사례를 일반화하면 이렇습니다.

| 설명 유형 | 점검 |
|-----------|------|
| "0, 4, 8, 11, 12는 다항식 계수가 1인 위치다" | 다항식은 16, 12, 5, 0이라 **숫자가 다르다.** 틀림 |
| "`16 - 차수`로 매핑된다" | 4와 11만 우연히 맞고 0, 8, 12는 설명되지 않는다. 틀림 |
| "코드는 `data_in(0)`이 먼저 들어간다고 가정했다" | 직접 전개하면 `data_in(15)`가 먼저다. **틀림** |
| "x^13 + x^4 + 1이 흔한 PRBS13 다항식이다" | 주기 7,161이라 최대 길이 아님. **틀림** |
| "피보나치 LFSR은 본질적으로 직렬이다" | 모든 LFSR은 병렬화된다. **틀림** |
| "이 식은 문헌에서 검증된 전개식이다" | 근거 문헌에 해당 전개식이 없는 경우가 있다. 출처를 직접 확인 |

이 표의 맨 아래가 중요합니다. **AI가 "검증된 식"이라고 말해도, 누가 줬든 대조 가능한 방법으로 직접 확인해야 합니다.**

- 직렬 모델로 N스텝 돌려 비교한다.
- 생성기 코드라면 식을 다시 생성해 본다.
- 주기와 확인값을 측정한다.
- **모르는 것은 "모른다"고 답하라고** 요청한다. 틀린 근거를 만들어 내는 것보다 낫다.

# 5. 점검표

병렬 CRC/PRBS를 쓰기 전에 다음을 확인합니다.

1. **직렬 모델**(Python 등)을 만들었는가
2. 병렬 식이 직렬 모델과 **단위 입력 전부**(또는 임의 입력 여러 번)에서 일치하는가
3. CRC는 **확인값**(예: "123456789" → 0x29B1)이 나오는가
4. PRBS는 **주기**가 2^n - 1인가
5. **비트 순서(MSB/LSB first)** 와 **바이트 순서**를 정했는가
6. 대상 규격의 **초기값, 입출력 반전, 최종 XOR**을 확인했는가
7. 다항식 **표기 규칙**을 확인했는가
8. 상태와 출력을 분리했는가 (끼워 넣는 데이터가 있다면)
9. 출력 폭을 바꿀 때 **스텝 수를 맞춰 다시 풀었는가**
10. 다항식이 **기약인지**(작은 다항식으로 나눠 보기)와 **규격의 다항식과 같은지** 확인했는가
11. PRBS 체커의 오류 수를 BER로 바꿀 때 **오류 배수**를 감안했는가

# What I Learned

- 병렬 식 검증의 기준은 **직렬 모델**이다. 같은 입력을 N스텝 돌린 결과와 같아야 한다.
- CRC는 **확인값**, PRBS는 **주기**로 한 번에 점검한다.
- 식은 **집합(대칭차)으로 N번 풀어서** 직접 만들 수 있고, 생성기 없이도 검증된다.
- 비트 순서, 바이트 순서, 반전, 다항식 표기가 가장 흔한 함정이다.
- 외워 둔 다항식도 **주기를 직접 측정**해야 한다. 인수분해되는 다항식은 처음부터 최대 길이가 될 수 없다.
- 병렬식은 선형이라 **단위 입력만 확인해도 완전히 검증**된다.
- 자기 동기화 체커는 **오류 하나를 여러 번 센다.**
- AI의 설명은 **그럴듯해도 틀릴 수 있어서**, 대조 가능한 방법으로 확인해야 한다.
