# Introduction

002에서 CRC의 병렬 식이 **1스텝 규칙을 N번 적용한 결과**라는 것을 봤습니다. 같은 원리를 **PRBS**(의사 난수 비트열)에 적용합니다.

- **PRBS12**: 12비트를 한 클럭에 내보내는 병렬 함수 (피보나치 점화식을 12번 풀어쓰기)
- **PRBS13**: 13비트 상태의 **갈루아 LFSR**을 병렬로 만들기

---

# 1. PRBS와 주기

PRBS는 LFSR이 만드는 **0과 1의 반복 열**입니다. n비트 LFSR이 **최대 길이**를 가지면 주기는 다음과 같습니다.

$$
2^{n} - 1
$$

| 종류 | 상태 길이 | 최대 주기 |
|------|-----------|-----------|
| PRBS12 | 12 | 4,095 |
| PRBS13 | 13 | 8,191 |

- 주기가 **최대**가 되려면 다항식이 **원시다항식(primitive polynomial)** 이어야 합니다.
- 상태가 전부 0이면 계속 0이라 **전부 0은 쓸 수 없습니다.** 초기값은 보통 전부 1입니다.

> 규격마다 다항식과 비트 순서가 다릅니다. 시험 장비가 기대하는 PRBS의 **정의**(다항식, 초기값, 비트 순서)를 먼저 확인해야 합니다.

구체적인 예를 들면 이렇습니다.

| 규격 | 정의하는 PRBS |
|------|---------------|
| ITU-T O.150 | PRBS7, 9, 11, 15, 23, 31 등. 장비에 따라 **출력을 반전**해 쓰기도 한다 |
| IEEE 802.3 (PRBS13Q 시험 패턴 등) | PRBS13으로 x^13 + x^12 + x^2 + x + 1 |

이 글의 PRBS13(x^13 + x^4 + x^3 + x + 1)은 **802.3의 PRBS13과 다른 다항식**입니다. 둘 다 최대 길이여도 비트열이 다르므로, 시험 장비의 PRBS13과는 맞지 않을 수 있습니다. 쓰는 장비와 규격의 정확한 정의는 **확인 필요**합니다.

# 2. PRBS12: 점화식을 12번 풀어쓰기

## 점화식

어떤 코드의 12비트 PRBS 함수가 이런 식을 가지고 있습니다.

```
oDQ(0) = iDQ(0) xor iDQ(3) xor iDQ(4) xor iDQ(7)
oDQ(1) = iDQ(1) xor iDQ(4) xor iDQ(5) xor iDQ(8)
oDQ(2) = iDQ(2) xor iDQ(5) xor iDQ(6) xor iDQ(9)
...
```

이것은 PRBS 비트열 u에 대한 **점화식 하나**입니다.

$$
u(n+12) = u(n) \oplus u(n+3) \oplus u(n+4) \oplus u(n+7)
$$

입력 `iDQ(0..11)`은 **이미 나온 비트 u(0)~u(11)** 이고, 출력 `oDQ(k)`는 **다음 12개 비트 u(12+k)** 입니다.

```
oDQ(k) = u(k) xor u(k+3) xor u(k+4) xor u(k+7)
```

## row 0~4는 같은 규칙을 한 칸씩 민 것

필요한 비트 u(k), u(k+3), u(k+4), u(k+7)이 **모두 입력 범위(0~11)** 에 있으면 점화식을 그대로 씁니다.

| row | 식 | 입력 번호 |
|-----|----|-----------|
| 0 | u0, u3, u4, u7 | 0, 3, 4, 7 |
| 1 | u1, u4, u5, u8 | 1, 4, 5, 8 |
| 2 | u2, u5, u6, u9 | 2, 5, 6, 9 |
| 3 | u3, u6, u7, u10 | 3, 6, 7, 10 |
| 4 | u4, u7, u8, u11 | 4, 7, 8, 11 |

row 4가 마지막인 이유는 **4 + 7 = 11**이기 때문입니다.

## row 5부터: 입력에 없는 비트가 나온다

row 5는 u5, u8, u9 그리고 **u12**가 필요합니다. 그런데 u12는 입력(0~11)에 없습니다. 방금 계산한 **row 0의 출력**이 u12입니다.

```
u12 = u0 xor u3 xor u4 xor u7        (row 0의 식)
```

그래서 u12를 row 0의 식으로 **대입**합니다.

$$
\text{row 5} = u_5 \oplus u_8 \oplus u_9 \oplus \underbrace{u_{12}}_{=\,u_0 \oplus u_3 \oplus u_4 \oplus u_7} = \{0, 3, 4, 5, 7, 8, 9\}
$$

코드에 있던 `0, 3, 4, 5, 7, 8, 9`가 어디서 나왔는지 설명됩니다. 이후 row도 같은 방식입니다. **GF(2)에서는 같은 비트가 두 번 나오면 지워집니다** (a xor a = 0).

| row | 점화식 그대로 | 입력에 없는 항 → 대입 | 지워지는 항 | 최종 입력 번호 |
|-----|---------------|----------------------|-------------|----------------|
| 5 | u5, u8, u9, u12 | u12 = {0,3,4,7} | 없음 | **0,3,4,5,7,8,9** |
| 6 | u6, u9, u10, u13 | u13 = {1,4,5,8} | 없음 | 1,4,5,6,8,9,10 |
| 7 | u7, u10, u11, u14 | u14 = {2,5,6,9} | 없음 | 2,5,6,7,9,10,11 |
| 8 | u8, u11, u12, u15 | u12 = {0,3,4,7}, u15 = {3,6,7,10} | 3, 7 | 0,4,6,8,10,11 |
| 9 | u9, u12, u13, u16 | u12, u13, u16 = {4,7,8,11} | 7, 8 (각 2번), 4 (3번이라 1번 남음) | 0,1,3,4,5,9,11 |
| 10 | u10, u13, u14, u17 | u13 = row 1, u14 = row 2, u17 = row 5 | 4, 8, 9 | 0,1,2,3,5,6,7,10 |
| 11 | u11, u14, u15, u18 | u14 = row 2, u15 = row 3, u18 = row 6 | 5, 9, 10 | 1,2,3,4,6,7,8,11 |

12개 행이 모두 원본 함수와 일치합니다 (직렬 점화식 시뮬레이션으로 확인).

> **unrolling = 아직 없는 비트를 이미 계산한 식으로 계속 갈아 끼우는 것**입니다. 행렬의 거듭제곱은 이것을 한 번에 적는 표기일 뿐입니다.

## 코드에서 다항식 읽기

"코드를 보고 어떤 다항식을 썼는지 알 수 있나?"에는 **있다**가 답입니다. **대입이 필요 없는 첫 행(row 0)** 이 점화식 자체이기 때문입니다.

- u(n+12) = u(n) + u(n+3) + u(n+4) + u(n+7)의 **특성다항식**은 x^12 + x^7 + x^4 + x^3 + 1입니다.
- 비트 번호를 반대로 세는 관례로 적으면 **역다항식** x^12 + x^9 + x^8 + x^5 + 1입니다.
- 둘 다 주기가 **4,095(= 2^12 - 1)** 인 것을 시뮬레이션으로 확인했습니다. (역다항식은 점화식 u(n+12) = u(n) + u(n+5) + u(n+8) + u(n+9)입니다.) 즉 최대 길이입니다.
- 다만 이 함수가 어느 **규격**의 PRBS12인지는 이 식만으로는 알 수 없습니다.

## 입력을 뒤집는 이유

그 코드는 입력을 뒤집어(`iDQ_inv`) 계산한 뒤 다시 뒤집어 내보냅니다. 함수 내부의 0번은 **시간상 가장 오래된 비트**이고, 뒤집기 때문에 바깥에서는 `iDQ(11)`이 가장 먼저 나온 비트입니다. 즉 **12비트 버스를 MSB부터 내보낸다**는 약속입니다. 비트 순서는 뒤집으면 결과가 달라지므로 이런 약속을 먼저 확인해야 합니다.

# 3. 함수를 회로에 붙일 때: 상태와 출력 분리

PRBS 함수를 클럭마다 반복 호출할 때 이런 코드를 쓰기 쉽습니다.

```vhdl
tx_data       <= PRBS12_N(prbs_in_data);
prbs_in_data  <= tx_data;
```

문제는 `prbs_in_data <= tx_data`가 **직전 클럭의 `tx_data`를 복사**한다는 점입니다. 중간에 다른 값(제어 심볼 등)을 `tx_data`로 내보내면 그 값이 **PRBS 상태에 덮여** 시퀀스가 끊깁니다.

해법은 **PRBS 상태 레지스터를 출력(`tx_data`)과 분리**하는 것입니다.

```vhdl
when IDLE_ST_PRBS =>
    prbs_state <= PRBS12_N(prbs_state);   -- 상태는 자기 자신으로만 갱신
    tx_data    <= PRBS12_N(prbs_state);   -- 출력은 상태를 복사
-- reset 에서 prbs_state <= (others => '1');
```

이렇게 하면 중간에 다른 데이터가 끼어들어도 PRBS는 **멈춘 자리에서 이어집니다.** (VHDL에서 `(others => 0)`이 아니라 `(others => '0')`처럼 문자 리터럴을 써야 하는 것도 함께 주의합니다.)

# 4. PRBS13: 갈루아 LFSR

13비트 PRBS는 상태 레지스터가 **갈루아 구조**였습니다. 다항식은 다음과 같습니다.

$$
x^{13} + x^{4} + x^{3} + x + 1 \quad (\text{0x201B})
$$

## 1스텝 규칙

왼쪽 시프트 갈루아 LFSR은 한 클럭에 다음만 합니다. 맨 위 비트 `s(12)`가 `fb`이고, 탭 x^0, x^1, x^3, x^4 자리에 `fb`가 섞입니다.

```
fb = s(12)
s'(0) = fb                    -- x^0
s'(1) = s(0) xor fb           -- x^1
s'(2) = s(1)
s'(3) = s(2) xor fb           -- x^3
s'(4) = s(3) xor fb           -- x^4
나머지 s'(i) = s(i-1)
```

## 13번 적용하면

13스텝을 풀면 원래 비트는 모두 위로 빠져나가고, **탭에서 섞인 fb들이 위로 올라간 자취**가 남습니다. 결과는 다음과 같습니다 (현재 상태 s의 어떤 비트들을 XOR하면 다음 비트가 되는지).

| next 비트 | 현재 상태 s의 비트들 |
|-----------|----------------------|
| 0 | 0, 9, 10, 12 |
| 1 | 0, 1, 9, 11, 12 |
| 2 | 1, 2, 10, 12 |
| 3 | 0, 2, 3, 9, 10, 11, 12 |
| 4 | 0, 1, 3, 4, 9, 11 |
| 5 이상 | 아래 비트가 한 칸 올라온 것 (예: 5 = 1, 2, 4, 5, 10, 12) |

## 비트 0과 비트 1은 왜 다른가

흔한 의문이 이것입니다.

> "next(0)은 {0, 9, 10, 12}인데 왜 next(1)은 {0, 1, 9, 11, 12}인가? 12, 9, 0은 시프트가 안 되나?"

- **시프트는 모두 한다.** s(12)가 여러 식에 다시 나타나는 것은 1스텝 때 0, 1, 3, 4번에 **복사된 fb(= s12)** 가 위로 올라가 다시 fb가 되기 때문이다. 시프트를 안 해서가 아니라 **복사되어 돌아오는 것**이다.
- `next(1)` = `next(0)` xor (13번째 스텝의 fb). 13번째 fb는 {1, 10, 11}이고 이것을 `next(0)`={0, 9, 10, 12}에 더하면 1과 11이 더해지고 **10은 지워져** {0, 1, 9, 11, 12}가 된다.
- `next(2)`는 탭이 없는 자리라 **한 스텝 전 `next(1)`의 값이 그대로 올라온 것**이고, 한 스텝 전의 맨 위 fb가 빠진다.

# 5. 피보나치도 병렬이 된다

"피보나치 방식은 병렬 계산이 안 된다"는 말은 틀립니다. **LFSR은 선형이므로 몇 스텝이든 한 클럭에 풀 수 있습니다.** PRBS12 함수가 바로 **피보나치 점화식을 12번 푼 병렬 코드**입니다.

PRBS13도 같은 방식으로 풀 수 있습니다. 같은 다항식에서 **같은 비트열을 만들고**, 레지스터 안의 상태 표현만 다릅니다.

$$
u(n+13) = u(n) \oplus u(n+1) \oplus u(n+3) \oplus u(n+4)
$$

# 6. PRBS13을 16비트로 내보내기

PRBS13을 16비트 버스로 내보내려고 이렇게 패딩하면 안 됩니다.

```vhdl
tx16 <= "000" & prbs13;      -- 잘못된 방법
```

상위 3비트가 항상 0이라 **PRBS13 비트열이 아닙니다.** 13은 **상태 길이**일 뿐이고 출력 폭은 자유입니다. **한 클럭에 16스텝**을 풀면 됩니다.

- 상태는 13비트 그대로 둡니다.
- **출력 16비트**는 16스텝 동안 나온 새 비트 u(13) ~ u(28)입니다.
- 처음 9개(u13~u21)는 점화식 그대로이고, 그 뒤부터는 PRBS12의 row 5처럼 **대입**해서 나옵니다.

| 출력 비트 | 입력 번호 (현재 13비트 윈도우 u(0) ~ u(12)) |
|-----------|----------------------|
| u13 | 0, 1, 3, 4 |
| u14 | 1, 2, 4, 5 |
| ... | (한 칸씩 밀림) |
| u21 | 8, 9, 11, 12 |
| u22 | 0, 1, 3, 4, 9, 10, 12 |
| u23 | 0, 2, 3, 5, 10, 11 |
| u24 | 1, 3, 4, 6, 11, 12 |
| u25 | 0, 1, 2, 3, 5, 7, 12 |
| u26 | 0, 2, 6, 8 |
| u27 | 1, 3, 7, 9 |
| u28 | 2, 4, 8, 10 |

- **다음 상태**는 마지막 13비트 u(16) ~ u(28)입니다.
- 이렇게 만든 점화식의 주기는 **8,191**입니다 (시뮬레이션 확인).
- 16비트 버스의 **어느 비트가 먼저 나가는지**는 상대 장비(PRBS 체커)의 정의에 맞춰야 합니다.

# 6-1. 받는 쪽: PRBS 체커

지금까지는 생성기만 봤습니다. 받는 쪽에서는 **자기 동기화 체커**를 많이 씁니다.

```
받은 비트 ──▶ [ 13비트 상태 ] ──▶ 점화식으로 "다음 비트" 예측
     │                                    │
     └──────────── 비교 (XOR) ◀────────────┘
                     │
                  1이면 오류
```

- 받은 비트를 그대로 상태 레지스터에 밀어 넣고, 점화식으로 다음 비트를 **예측**해 실제로 받은 비트와 비교합니다.
- 상태를 받은 비트로 채우므로 **동기를 따로 맞출 필요가 없습니다.** 13비트만 받으면 바로 동기됩니다.

다만 함정이 하나 있습니다. **비트 오류 하나가 여러 번 세어집니다.** 잘못 받은 비트가 상태에 들어가 있는 동안 그 비트를 쓰는 예측마다 다시 틀리기 때문입니다. 점화식의 항이 4개(u(n), u(n+1), u(n+3), u(n+4))라면, 실제 오류 하나가 비교 결과에서 **여러 개의 오류**로 나타납니다. 그래서 체커의 오류 수를 BER로 바꿀 때는 이 **배수**를 감안해야 합니다(004).

# 7. 갈루아와 피보나치는 같은 표를 가로, 세로로 읽는다

PRBS13의 x^(13+j) mod p를 표로 만들면 두 가지로 읽을 수 있습니다.

| j | x^(13+j) mod p에 남는 차수 |
|---|---------------------------|
| 0 | 0, 1, 3, 4 |
| 1 | 1, 2, 4, 5 |
| ... | (한 칸씩 밀림) |
| 8 | 8, 9, 11, 12 |
| 9 | 0, 1, 3, 4, 9, 10, 12 |
| 10 | 0, 2, 3, 5, 10, 11 |
| 11 | 1, 3, 4, 6, 11, 12 |
| 12 | 0, 1, 2, 3, 5, 7, 12 |

- **세로(열)로 읽으면 갈루아 병렬 식**입니다. 차수 0이 들어 있는 j(= 0, 9, 10, 12)를 모으면 next(0)입니다.
- **가로(행)로 읽으면 피보나치 병렬 식**입니다. j번째 행이 새 비트 u(13+j)의 XOR 목록이고, 위 16비트 출력 표와 같습니다.
- 행 0~8이 한 칸씩 밀리는 같은 모양이고 **행 9부터 갑자기 길어지는 것**은 PRBS12의 row 4와 row 5 사이에서 본 현상과 같습니다. 입력 범위를 넘는 비트가 나오는 순간 대입이 시작됩니다.

# What I Learned

- PRBS는 LFSR의 출력이고, 최대 주기 2^n - 1을 위해서는 **원시다항식**이어야 한다.
- 병렬화는 **점화식을 N번 풀어쓰는 것(unrolling)** 이다. 아직 없는 비트를 이미 계산한 식으로 갈아 끼우고, **같은 비트가 두 번 나오면 지운다.**
- 코드의 첫 행(대입이 필요 없는 행)에서 **다항식을 읽을 수 있다.**
- PRBS 함수를 회로에 붙일 때는 **상태 레지스터와 출력을 분리**해야 중간에 다른 데이터가 끼어들어도 시퀀스가 이어진다.
- 갈루아 LFSR은 **fb가 탭에서 섞여 위로 올라간 자취**로 병렬 식이 만들어진다. 12, 9, 0이 반복되는 것은 시프트를 안 해서가 아니라 복사된 fb가 돌아오기 때문이다.
- **피보나치도 병렬화된다.** 같은 표를 가로로 읽으면 피보나치, 세로로 읽으면 갈루아다.
- 13은 상태 길이이고 **출력 폭은 자유**다. `"000" & prbs13` 패딩은 틀린 방법이다.
- 같은 이름(PRBS13)이라도 **규격마다 다항식이 다르다.** 시험 장비의 정의를 먼저 확인한다.
- 자기 동기화 체커는 동기가 쉽지만 **오류 하나를 여러 번 센다.**
